# White-label миграция на новый домен

## 1. Цель документа

Этот документ описывает, как перенести проект на новый домен или сделать white-label копию для другого проекта.

## 2. Минимальный перенос

### 2.1. Файлы
1. Скопировать все файлы проекта
2. Убедиться, что `.env` не попал в git
3. На новом сервере создать `.env` с новыми данными

### 2.2. База данных
1. Сделать дамп текущей БД
2. Создать новую БД
3. Импортировать дамп
4. Обновить `DATABASE_URL` в `.env`

### 2.3. Настройки
1. Зайти в админку
2. Обновить:
   - название сайта
   - URL сайта
   - логотип
   - favicon
   - интеграции (при необходимости)

### 2.4. Первый запуск
1. Проверить главную
2. Проверить админку
3. Проверить мониторинг
4. Проверить cron

## 3. Полный white-label

### 3.1. Контент
Решить, что переносим:
- [ ] только структуру (без контента)
- [ ] структуру + офферы
- [ ] структуру + статьи
- [ ] структуру + теги
- [ ] всё полностью

### 3.2. Офферы
Если переносим офферы:
- обновить партнёрские ссылки;
- проверить логотипы;
- перепривязать теги.

### 3.3. Статьи
Если переносим статьи:
- проверить актуальность;
- обновить мета-теги;
- проверить обложки.

### 3.4. Теги
Если переносим теги:
- обновить SEO-тексты;
- обновить фичи;
- перепривязать офферы.

### 3.5. Города
Если переносим города:
- проверить актуальность;
- обновить SEO;
- проверить город+тег.

## 4. Интеграции

### 4.1. Почта
- обновить SMTP;
- обновить email обратной связи;
- протестировать отправку.

### 4.2. AI
- обновить YandexGPT ключи (если новые);
- обновить YandexART (если новые);
- проверить генерацию.

### 4.3. Индексация
- обновить Google Service Account;
- обновить Яндекс.Вебмастер;
- протестировать отправку URL.

### 4.4. Аналитика
- обновить Яндекс.Метрику;
- обновить Google Analytics.

## 5. Cron и планировщик

### 5.1. Cron
- настроить cron на новом сервере;
- проверить health-ping;
- проверить бэкапы.

### 5.2. Планировщик
- проверить настройки генерации;
- проверить логи;
- проверить счётчики.

## 6. Безопасность

### 6.1. Админка
- сменить пароль админа;
- включить 2FA;
- настроить IP whitelist (если нужно).

### 6.2. Данные
- убедиться, что старые секреты не попали в git;
- создать новые service account JSON;
- создать новые настройки Яндекс.Вебмастера.

### 6.3. Доступы
- проверить права на папки;
- проверить `.htaccess`;
- проверить недоступность служебных директорий.

## 7. Финальный чек-лист

### 7.1. Технический
- [ ] Файлы скопированы
- [ ] БД импортирована
- [ ] `.env` настроен
- [ ] Интеграции обновлены
- [ ] Cron настроен
- [ ] Планировщик работает
- [ ] Мониторинг зелёный

### 7.2. Контентный
- [ ] Офферы перенесены/обновлены
- [ ] Статьи перенесены/обновлены
- [ ] Теги перенесены/обновлены
- [ ] Города перенесены/обновлены
- [ ] SEO сгенерировано

### 7.3. Безопасность
- [ ] Пароль изменён
- [ ] 2FA включена
- [ ] IP whitelist настроен
- [ ] Секреты обновлены

### 7.4. Документация
- [ ] Документация скопирована
- [ ] Примеры обновлены
- [ ] Ссылки работают

## 8. Что делать после переноса

1. Пройти production-audit
2. Пройти этот чек-лист
3. Проверить работу всех модулей
4. Проверить мониторинг
5. Проверить cron
6. Проверить интеграции

## 9. Типичные проблемы

### 9.1. Не работает почта
- проверить SMTP;
- проверить firewall;
- проверить логи.

### 9.2. Не работает генерация
- проверить API ключи;
- проверить логи;
- проверить мониторинг.

### 9.3. Не работает индексация
- проверить Service Account;
- проверить Яндекс.Вебмастер;
- проверить логи.

### 9.4. Не работает cron
- проверить права;
- проверить путь к PHP;
- проверить логи cron.

## 10. Рекомендации

- делать перенос в тестовом окружении;
- после переноса проходить чек-листы;
- документировать все изменения;
- сохранять старые секреты до полного перехода.
