# Стабилизационный чек-лист проекта

Этот документ нужен после любых крупных правок, релизов и миграций.

## 1. Быстрая проверка сайта

Проверьте вручную:
- [ ] главная `/`
- [ ] каталог `/zajmy`
- [ ] каталог `/kredity`
- [ ] `/karty/kreditnye`
- [ ] `/karty/debetovye`
- [ ] случайный оффер `/offer/...`
- [ ] случайная статья `/articles/...`
- [ ] `/robots.txt`
- [ ] `/sitemap.xml`
- [ ] `/llms.txt`
- [ ] `/api/health`

## 2. Проверка админки

- [ ] `/admin/login` открывается
- [ ] вход работает
- [ ] 2FA включается / отключается
- [ ] вкладки админки переключаются без JS-ошибок
- [ ] Настройки сохраняются
- [ ] Мониторинг открывается

## 3. Проверка критичных модулей

### Контент
- [ ] создание оффера
- [ ] создание статьи
- [ ] редактирование тега
- [ ] генерация FAQ
- [ ] качество контента

### SEO
- [ ] SEO-тексты городов генерируются
- [ ] SEO-тексты city+tag генерируются
- [ ] очистка markdown/html работает
- [ ] индексация Google работает
- [ ] индексация Яндекс работает
- [ ] позиции загружаются

### Аналитика
- [ ] воронка по офферам открывается
- [ ] debug воронки работает
- [ ] финансовая аналитика открывается
- [ ] партнёрские ссылки проверяются

### Система
- [ ] SMTP тест отправляется
- [ ] обратная связь отправляет письмо
- [ ] розыгрыши открываются
- [ ] мониторинг показывает статусы

## 4. Проверка фоновых задач

- [ ] `scheduler-fire.log` обновляется
- [ ] автостатьи создаются
- [ ] автоотзывы создаются
- [ ] maintenance-cron отрабатывает
- [ ] бэкап создаётся

## 5. Проверка логов

- [ ] в Мониторинге нет новых critical/fatal ошибок
- [ ] нет предупреждений, связанных с parse error
- [ ] нет ошибок подключения к внешним API
- [ ] нет предупреждений SMTP

## 6. Проверка данных и кэша

- [ ] page cache очищается
- [ ] api cache очищается
- [ ] новые данные попадают в публичные страницы
- [ ] новые статьи получают `cover_image`
- [ ] новые URL попадают в `url_index_tracker`

## 7. Когда нужно обязательно выполнять этот чек-лист

- после релиза в production;
- после изменения `config.php`, `index.php`, `layout.php`;
- после новых интеграций AI/API;
- после правок входа/2FA;
- после изменения маршрутов;
- после миграций БД.

## 8. Минимум перед завершением релиза

Если нет времени на полный цикл, минимум:
- [ ] `/api/health`
- [ ] главная
- [ ] случайный оффер
- [ ] админка вход
- [ ] Мониторинг
- [ ] SMTP тест
- [ ] лог ошибок пуст или без critical

## 9. Рекомендация

Хорошая практика — после каждого большого набора правок:
1. очистить кэш;
2. пройти этот чек-лист;
3. сохранить дату проверки и результат.
